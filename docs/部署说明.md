# 运行与部署

前端可以独立运行体验数据。连接真实服务时，需要 Java 应用、MySQL、Redis 和 Kafka。容器方式会一并启动这些服务，本地开发也可以连接自己准备的依赖。

## 本地开发

使用 JDK 17、Maven 3.9、Node.js 20+、MySQL 8、Redis 7。前端运行与构建没有第三方包依赖。

先将 [hmdp.sql](../src/main/resources/db/hmdp.sql)导入一个独立数据库。可在 MySQL 客户端运行：

```sql
SOURCE /absolute/path/to/jingyue/src/main/resources/db/hmdp.sql;
```

脚本创建 `shanhai_ticket`，包含基础表、订单联合唯一索引、点赞关系表和异步点赞状态表，以及虚构目的地、作者和手记。活动票种通过应用接口初始化，让数据库提交后的库存预热逻辑正常执行。

连接参数由 [application.yaml](../src/main/resources/application.yaml)读取：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SERVER_PORT` | `8081` | 应用端口 |
| `DB_URL` | 本机 `shanhai_ticket` JDBC 地址 | MySQL 连接 |
| `DB_USERNAME` | `shanhai` | 数据库用户 |
| `DB_PASSWORD` | 空 | 自行配置的数据库密码 |
| `REDIS_HOST` / `REDIS_PORT` | `127.0.0.1` / `6379` | Redis 连接 |
| `REDIS_DATABASE` | `8` | 应用使用的 Redis 库 |
| `REDIS_PASSWORD` | 空 | Redis 认证 |
| `KAFKA_BOOTSTRAP_SERVERS` | `127.0.0.1:9092` | Kafka 地址 |
| `VOUCHER_CACHE_MODE` | `mysql` | 票种列表查询方式，可选 `redis`、`caffeine` |

PowerShell 示例，用户名与密码请替换为自己的配置：

```powershell
$env:DB_USERNAME = 'shanhai'
$env:DB_PASSWORD = '填写自己的数据库密码'
$env:REDIS_DATABASE = '8'
mvn spring-boot:run
```

macOS / Linux：

```bash
export DB_USERNAME=shanhai
export DB_PASSWORD='填写自己的数据库密码'
mvn spring-boot:run
```

另开终端，项目根目录执行：

```bash
node frontend/scripts/seed-tickets.mjs
cd frontend
npm run dev
```

打开 `http://127.0.0.1:5173`，选择“连接真实服务”。手机号验证码由开发后端生成，查看后端调试日志中的验证码完成登录。

`.env` 用于 Docker Compose；Maven 启动不会自动读取根目录 `.env`，本地运行需在当前终端设置上述环境变量。前端代理地址可用 `API_TARGET` 调整。

## Docker Compose

复制 `.env.example` 为 `.env`，设置两个不同的数据库密码。在根目录执行：

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8080/api/shop-type/list
docker compose --profile tools run --rm seed
```

页面位于 `http://127.0.0.1:8080`。Nginx 提供静态页面，将 `/api` 请求转发给 Java 服务；MySQL、Redis 和 Kafka 通过容器网络通信。

`seed` 使用应用接口创建虚构活动票。相同票种已存在时会跳过，不重置库存。SQL 仅在新的 MySQL 数据卷首次初始化时执行。

| 数据卷 | 内容 |
| --- | --- |
| `mysql-data` | 用户、目的地、手记、订单与点赞数据 |
| `redis-data` | 登录态、缓存、资格和待发送事件 |
| `kafka-data` | Kafka 日志 |
| `uploads` | 本地上传文件 |

更新源码后再次运行 `docker compose up -d --build`。普通停止使用 `docker compose down`，保留数据卷；迁移时另行备份数据。

## 服务器入口

Compose 将 Web 入口绑定到服务器 `127.0.0.1:8080`。服务器可以使用 Nginx 或 Caddy 配置域名与 HTTPS，并代理到这个地址。数据库与消息服务不需要映射到公网。

当前验证码通过开发日志获取，适合自行搭建的开发体验环境。给外部用户开放真实登录时，需要接入自己的短信发送与验证码保护，并配置写入接口的访问权限。

只想展示页面时，可将 `frontend` 构建后的 `dist/` 放到静态托管服务。页面使用 hash 路由和相对资源路径，可部署在仓库子路径；静态托管展示内置体验数据。

## 可选并发处理配置

默认点赞走数据库事务，可通过 `high-concurrency` profile 开启异步点赞和批量订单消费。初始化脚本已包含对应表。该 profile 的开关、批大小、连接池与队列容量见 [application-high-concurrency.yaml](../src/main/resources/application-high-concurrency.yaml)。

切换写入路径前先停止写入并排空待处理事件，再改变配置。仅希望启用批处理时，也可以单独设置相关属性；Nginx 已提供前端时，无需开启嵌入式静态页面入口。

## 测试命令

后端订单与点赞测试在本机启动临时 Redis，使用 H2 和内嵌 Kafka，不要求启动完整业务环境：

```bash
mvn -Dtest="com.hmdp.order.*Test,com.hmdp.like.*Test" test
```

Windows 如未将 Redis 加入 PATH：

```powershell
mvn '-Dtest=com.hmdp.order.*Test,com.hmdp.like.*Test' '-Dhmdp.test.redis-executable=C:/path/to/redis-server.exe' test
```

根包中的课程环境测试需要自行准备对应的 MySQL / Redis。CI 运行上面的隔离测试，再构建应用；前端使用 `npm test` 和 `npm run build`。
