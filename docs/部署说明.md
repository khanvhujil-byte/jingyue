# 景约部署说明

## Docker

需要 Node.js 20+、Docker Engine 与 Docker Compose v2。仓库根目录执行：

```bash
node scripts/init-compose-env.mjs
docker compose config --quiet
docker compose up -d --build
```

初始化脚本只在 `.env` 不存在时生成数据库密码和票券签名密钥。Compose 使用独立数据库 `jingyue_ticket_dev`，首次启动按文件名顺序执行 `backend/src/main/resources/db/*.sql`。

等待 <http://127.0.0.1:5190/api/v1/health> 正常，再运行 `node scripts/prepare-demo.mjs`，打开 <http://127.0.0.1:5190/#/>。脚本只预热和发布原演示票种，不覆盖既有库存，也不恢复主动暂停的批次。

| 服务 | 本机入口 |
| --- | --- |
| 页面与 API 代理 | `127.0.0.1:5190` |
| Spring Boot | `127.0.0.1:8089` |
| MySQL | `127.0.0.1:3318` |
| Redis | `127.0.0.1:6398` |
| Kafka | `127.0.0.1:19092` |

端口默认绑定本机；已有服务占用时应先选择其他端口或停止冲突的实例。数据位于独立 Compose 卷，普通停止使用 `docker compose down`，更新使用 `docker compose up -d --build`。

## 原生运行

需要 JDK 17、Maven 3.9、Node.js 20+、MySQL 8、Redis 7 和 Kafka。新建以 `jingyue_` 开头的独立数据库，给专属账号授权，再在该库按文件名顺序执行 `backend/src/main/resources/db/*.sql`。创建 Kafka 主题 `jingyue-ticket-orders-v1`，配置 16 个分区。

| 环境变量 | 默认值 / 用途 |
| --- | --- |
| `JINGYUE_MYSQL_HOST` / `JINGYUE_MYSQL_PORT` | `127.0.0.1` / `3318` |
| `JINGYUE_DATABASE` / `JINGYUE_MYSQL_USER` | `jingyue_ticket_dev` / `jingyue` |
| `JINGYUE_MYSQL_PASSWORD` | 数据库密码 |
| `JINGYUE_REDIS_HOST` / `JINGYUE_REDIS_PORT` | `127.0.0.1` / `6398` |
| `JINGYUE_REDIS_PASSWORD` | 可选 Redis 密码 |
| `JINGYUE_KAFKA` | `127.0.0.1:19092` |
| `JINGYUE_TICKET_SIGNING_KEY` | 长度至少 32 的持久随机密钥 |
| `JINGYUE_DEVELOPMENT` | 演示环境设为 `true`，创建示例数据并开放演示账号验证码 |
| `JINGYUE_MOCK_PAYMENT` | 演示环境设为 `true`，允许模拟支付 |
| `JINGYUE_UPLOAD_DIR` | 默认 `.runtime/uploads` |
| `JINGYUE_PORT` / `JINGYUE_WEB_PORT` | `8089` / `5190` |

`.env` 默认仅供 Compose 使用；原生启动要把值设置到启动进程的环境中。保留签名密钥才能继续验证已签发的电子票。

```bash
mvn -B -f backend/pom.xml -DskipTests package
java -jar backend/target/jingyue-ticket-0.0.1-SNAPSHOT.jar
```

另开终端，在仓库根目录启动前端并初始化演示票种：

```bash
node frontend/server.mjs
node scripts/prepare-demo.mjs
```

代理保留完整 `/api/v1/` 路径。Windows 的 `scripts/start.ps1` 是原开发机辅助脚本，内含工具路径；通用环境使用上述命令或 Docker。

## 服务器与手机

推荐在同一域名下由 Nginx 或 Caddy 将请求转发到 `127.0.0.1:5190`，配置 HTTPS。手机打开该域名即可；浏览器不直接连接数据库、Redis 或 Kafka。

局域网体验可用反向代理提供入口，或设置 `JINGYUE_WEB_BIND` 为局域网地址后运行 Node 服务。手机和电脑需要在同一网络，防火墙允许所选端口。Docker 默认绑定 `127.0.0.1`，需由代理提供外部入口。

## 验证

完整 `TicketIntegrationTest` 会创建景点、订单和故障注入数据，应只在新建的独立 MySQL、Redis、Kafka 环境中运行：

```bash
mvn -B -f backend/pom.xml test
```

配置该测试环境的连接变量、签名密钥和演示开关。GitHub Actions 中的 `backend` 工作流提供了独立环境示例。
