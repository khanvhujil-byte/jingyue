# 交易设计与接口

## 状态来源

Redis Lua 受理成功只代表预扣资格和待发送事件已建立；Kafka确认只代表消息已被broker接收；数据库提交后才是待支付订单；模拟支付事务成功后才生成电子票。

```
请求 UNKNOWN → PROCESSING → CREATED / REJECTED
订单 PENDING_PAYMENT → PAID → USED / EXPIRED
订单 PENDING_PAYMENT → CLOSED → 归还PENDING → RELEASED
```

请求号属于用户，同一请求号的SKU、配置版本和数量摘要必须一致。订单ID、用户ID、SKU等均以十进制字符串传输，价格为整数分，公开业务时间为带上海偏移的ISO格式。

## 并发与恢复

预扣库存、用户到订单资格映射、请求原结果、原事件、pending和修复屏障放在一个Redis Hash，由**同一条 HSET** 写入，Stream是投递索引。XADD失败可由journal重建；不依赖Lua运行时报错自动回滚。滑动窗口在同一脚本内检查，member使用唯一事件ID；原请求重试先返回原结果，不重复消耗下单额度。

发送服务仅在broker ACK后清pending和Stream；超时保留原订单号。消费批次按SKU、订单稳定排序，先按SKU升序加行锁，批量建立请求结果gate，汇总扣数据库库存，批量插入订单与资格，提交后确认offset。相同身份重放幂等，身份/版本冲突保留完整消息与原位置。隔离记录必须提交成功后才能跨过消费位置。

创建与运营拒绝共用按orderId唯一的数据库gate。REJECTED不能被迟到创建复活；CREATED包含历史CLOSED订单，重放不能重复扣减。死锁有限重试整个事务，事务内不等待Redis/Kafka。

支付、关闭与核销统一先锁SKU、再锁订单。支付金额来自订单快照，成功支付记录及票券均按订单唯一；失败不改变待支付。关闭事务同时关闭订单、归还DB库存、按原orderId删除DB资格、写唯一RELEASE待办。Redis归还核对epoch、原资格与永久去重标记，在一次HSET中加库存/清资格/写证据；旧释放重放不能删除新订单资格。

二维码由随机nonce、票ID、版本和HMAC-SHA256签名组成，不能根据订单号猜测。只有本人票券接口返回完整凭证。核销检查角色、景点授权、PAID、未使用、`validFrom <= now < validUntil`，一次事务写USED与唯一流水；重复核销返回首次时间。

## 接口

| 方法 / 路径（均含/api/v1） | 用途 |
| --- | --- |
| POST auth/code、auth/login；GET auth/me；POST auth/logout | 演示登录与注销 |
| GET attractions、attractions/{id}、attractions/{id}/ticket-calendar | 筛选景点、详情、30天已配置日期票 |
| POST ticket-requests | skuId、configVersion、clientRequestId；固定一张 |
| GET ticket-requests/{requestId} | 本人原请求结果 |
| GET ticket-requests/current?skuId= | 本人SKU当前有效申请 |
| GET orders、orders/{id} | 本人订单与历史 |
| POST orders/{id}/mock-payment | outcome=SUCCESS、FAIL、REPEAT；不接受可信金额 |
| POST orders/{id}/cancel | 关闭本人未支付订单 |
| GET orders/{id}/ticket | 本人签名电子票 |
| POST redemptions | credential、clientRequestId；授权核销员 |
| GET/POST travel-notes；GET/PUT travel-notes/{id} | 游记读取、发布、仅作者编辑 |
| PUT travel-notes/{id}/like | 明确 liked=true/false，保留原异步版本投影 |
| POST media；GET media/{id} | PNG/JPEG安全上传；5MB，内容/尺寸/归属校验 |
| admin/attractions、ticket-products、ticket-skus | 运营创建与管理 |
| POST admin/ticket-skus/{id}/{warmup,publish,pause,resume,end,archive} | 显式售卖状态变更，记录审计 |
| GET admin/reconciliation、failures、audit | 只读对账、受限异常与审计 |
| POST admin/failures/{id}/{retry,reject} | 原事件重试或持久拒绝；reject需reason |

身份来源只取Bearer token对应的Redis登录态，业务不信任请求体userId。只公开GET景点/游记/media及指定演示登录入口。所有管理写操作服务端校验ADMIN，核销要求REDEEMER及scope。

失败返回 `code/message/requestId/retryAfter`。429包含Retry-After；UNKNOWN不等于失败。前端在sessionStorage按用户和SKU保留原请求，刷新不POST；即刻查询一次以快速显示已落库订单，随后按250/500毫秒、1/2/4/5秒加抖动退避，约60秒后停自动查询。隐藏页面停定时器，恢复时继续查询。登录、库存、支付、核销不读取景点公共L1缓存。


## 大批量到期与日志归档

到期任务每秒按SKU分组处理有界批次。按固定顺序锁SKU及订单，对仍待支付且已到期的订单汇总归还数据库库存、删除对应资格并批量写唯一RELEASE待办；已支付票到期仅标记过期，不归还库存。Redis批量归还复用同一幂等脚本，只有已确认成功的待办才能在一个SQL事务中标记完成。

CREATED/REJECTED且至少60秒、无待发送/修复/归还修复的订单可清理Redis临时req/event/pending/repair/queued字段。数据库请求gate、库存、有效资格和永久released去重保留；归档后原请求仍先查数据库，旧创建消息仍不能重复扣库存。

恢复扫描跨定时轮次保存HSCAN cursor，避免大Hash中每次从0开始且被有界批次截断，导致后部修复记录长期不可达。每轮工作仍有上限，不用一次长Lua遍历整个业务Hash。

`GET admin/metrics`受ADMIN保护，展示HTTP计数、服务处理峰值、Hikari等待、JVM堆与线程、Redis内存。指标采样异常不能解释为积压为零。缓存TTL与受理/查询/支付/核销配额均可配置。
