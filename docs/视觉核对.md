# 景约视觉与浏览器核对

参考：output/imagegen/01-home.png 至06-mobile.png。正式图片来自独立素材生成，保存为frontend/assets的WebP；没有把整张设计稿作为界面。

使用Playwright+Edge（Browser plugin not available）。桌面按首页1205×1305、详情1330×1182检查；手机检查360、390、430×844。六个主要界面已分别实现：景点首页、详情、订单、运营、核销及手机布局。

| 比较项 | 参考与实现核对 | 处理 |
| --- | --- | --- |
| 品牌与首屏文案 | 景约；把周末，交给山水；发现一处好风景，预约下一段旅程 | 保留，无山海之间旧品牌 |
| 配色与媒体 | 白底、蓝色按钮、湖谷山水主视觉 | 使用独立生成的同风格风景图，无额外遮色层 |
| 首页布局 | 顶部导航、左侧标题和搜索、四列景点、双游记横排 | 与参考结构一致；真实分页增加了纵向高度 |
| 字体与控件 | 明确标题/正文/辅助层级，统一按钮、表单及表格 | 控件字号单独定义，移动端收紧间距 |
| 图标 | 蓝色线性心形、账号下拉 | 心形与下拉改为真实SVG，状态使用ARIA属性 |
| 详情结果 | 日期选择与当前页待支付结果 | 状态由服务器返回，不能用稿中假订单充当真实数据 |
| 图片画廊 | 稿中三图，正式资料目前每景点一张 | 只展示已配置照片，不复制同一图假装多角度 |
| 价格/点赞/作者 | 稿中占位价格、点赞数和头像 | 使用真实种子信息；首页引导查看日期票，不复制假价格/点赞数 |
| 移动端 | 搜索换行、双列景点、购票区在简介前 | 360/390/430首页与详情、390电子票无横向溢出；手机详情恢复同日期与订单 |

已实际用view_image对照设计稿与最新截图。保留上述真实数据和素材差异，不宣称像素完全一致。

浏览器已验收：取消再购、原位待支付、刷新不重复提交、支付失败/成功/重复、二维码反解、授权及重复核销、丢失下单回包后恢复、图片上传及安全正文、作者编辑、点赞失败回退和校正、点赞/取消、越权编辑拒绝、运营创建/编辑/停用及对账页。

测试中注入了预期网络失败和503；无JavaScript运行异常。截图与临时浏览器脚本位于Codex可视化目录；有效票券凭证截图不进入GitHub源码包。
