# hm-dianping GitHub 发布

## 问题与目标

现有项目包含本地开发配置、未提交的后端扩展和独立文旅前端，缺少面向访客的根目录说明。发布到 khanvhujil-byte 账号下的公开 GitHub 仓库，让读者通过真实页面了解功能、理解核心链路并能自行启动。

## 开发范围

1. 核对当前工作区的功能、测试、运行依赖和原项目来源，保留已有修改。
2. 编写简洁 README，展示功能、技术特点、架构、实际页面截图、本地运行和容器部署。
3. 新增分章节《项目教学》，按概念、源码、练习组织，覆盖登录、缓存、秒杀资格、可靠事件投递、事务落库、点赞和限流。
4. 将后端连接配置参数化，提供无真实凭据的配置模板；补齐完整容器启动文件。
5. 检查待发布文件与历史中的敏感配置，排除本地数据库、日志、IDE/AI 工作目录、运行产物和真实账号资料；必要时使用隔离的发布副本，原始 Git 与 Gitee 远程保留。
6. 运行与发布改动相符的构建、测试和页面检查，创建公开仓库并验证上传内容。

## 成功标准

README 清楚区分体验数据与真实后端；不宣传支付、退款、核销等未实现能力；截图来自实际运行页面。所有源码与图片链接有效；配置不包含个人密码或密钥；文档命令与实现一致。保留原项目来源，不给第三方代码重新授权。GitHub 仓库归属正确，文件可匿名读取。

## 限制条件

只处理发布所需的文档、配置和部署适配，不重写秒杀、点赞等业务。测试不得操作现有生产或个人业务数据；页面取图使用独立体验数据。Docker 引擎或外部服务不可用时，明确区分配置验证与真实部署验证。

## 开发计划

源码与配置核对 → 发布配置及部署适配 → 文档与页面取图 → 构建及测试 → 文件与历史检查 → GitHub 发布并回查。
