# 文旅前端与既有后端的对应关系

这里是业务适配，不是重新实现库存与消息链路。Java 包、接口路径和兼容表名仍保留 hm-dianping 的命名。新站以“指定活动票种限量抢购”为范围，没有日期预约、场次或座位库存。

| 原有能力 | 文旅页面 | 实际接口 |
| --- | --- | --- |
| 店铺分类 | 目的地分类 | GET `/shop-type/list` |
| 按店铺名称搜索 | 景点/文旅场馆搜索 | GET `/shop/of/name?name=&current=1` |
| 按类型分页 | 山野、海岸、人文、艺术分类 | GET `/shop/of/type?typeId=&current=1` |
| 店铺详情 | 目的地详情、地址、开放时间 | GET `/shop/{id}` |
| 优惠券列表 | 指定活动票种列表 | GET `/voucher/list/{shopId}` |
| 手机验证码登录 | 旅人账号登录/注册 | POST `/user/code?phone=`、POST `/user/login` |
| token 身份恢复 | 我的景约 | GET `/user/me`，请求头 `authorization` |
| 热门博客 | 旅行手记 | GET `/blog/hot?current=1` |
| 博客详情/点赞用户 | 游记与喜欢的旅人 | GET `/blog/{id}`、GET `/blog/likes/{id}` |
| 点赞与取消 | 游记即时点赞 | PUT `/blog/like/{id}?liked=true/false` |
| 发布博客 | 发布文字游记与内置封面 | POST `/blog` |
| 我的博客 | 我写过的手记 | GET `/blog/of/me?current=1` |
| 关注 | 关注游记作者 | PUT `/follow/{userId}/{true/false}` |
| 关注动态 | 关注的旅人 | GET `/blog/of/follow?lastId=&offset=` |
| 用户签到 | 旅人签到 | POST `/user/sign`、GET `/user/sign/count` |
| 秒杀资格校验 | 活动门票限量抢购 | POST `/voucher-order/seckill/{voucherId}` |
| 本人订单状态 | 票夹的排队/创建结果 | GET `/voucher-order/status/{voucherId}` |

所有路径在浏览器经过 `/api` 代理。默认本地服务器移除 `/api`，转发至 `API_TARGET`，默认 `http://127.0.0.1:8081`。

## 字段含义

| 兼容字段/表 | 文旅业务含义 | 限制 |
| --- | --- | --- |
| `tb_shop`、`shopId` | 目的地/场馆 | 不把原餐饮内容偷偷改名伪装成景点 |
| `tb_shop_type` | 景点分类 | 独立示例数据使用 91001–91004 |
| `tb_blog` | 旅行手记 | 文字按纯文本显示，防止服务端内容注入脚本 |
| `tb_voucher` | 活动票种 | `payValue/actualValue` 沿用分为单位的金额 |
| `tb_seckill_voucher.stock` | 活动票种配额 | 非按日、场次或座位库存 |
| `beginTime/endTime` | 抢购受理展示期限 | 不是入园日期；前端禁用按钮不能代替服务端校验 |
| `tb_voucher_order` | 购票订单记录 | 创建完成不表示已付款或已核销 |
| `shop.avgPrice` | 目的地参考价 | 沿用后端的整数元单位，不与票价的分混用 |

## 交互与一致性

- 点赞立即反馈，发送明确目标状态；提交时锁定按钮，失败恢复，随后查询校正。不能仅凭超时认定服务端没有处理。
- 抢购前将本地待确认记录写入 sessionStorage；同票种只发一次 POST。受理后显示排队，只有状态接口返回 `CREATED` 才显示订单已创建。
- 受理后立即查询一次；未完成时再按1、2、4、5秒间隔及抖动查询，约一分钟后暂停。手动刷新立即发送GET，不重新抢购；刷新网页恢复查询。体验模式不额外制造网络或排队等待。
- 订单号解析保留 Java Long 精度，最终显示接口返回的十进制字符串。
- 本地记录按模式和当前用户隔离；模式切换或退出会停止轮询。服务端身份始终由 token 决定。
- 当前无历史订单列表接口，票夹仅追踪本浏览器会话提交的票种。不能把它描述为完整订单中心。
- 当前后端 `/user/logout` 返回功能未完成，因此按钮明确表示退出当前浏览器，仅清理本地凭据，不声称已撤销服务端 token。

## 没有伪造的功能

没有在线支付、退款、核销码、实名验证、日期预约、地图实时定位、评论、图片上传或真实短信。用户可用文字和本地原创封面发布游记。当前关注流展示一页，目的地、发现手记提供翻页。

## 旧项目与新项目数据

真实模式忠实展示后端返回的内容。原库仍有餐饮数据时，会展示原数据，不靠前端替换名称伪装业务迁移。要得到完整文旅场景，请在独立数据库运行公开包的初始化脚本，再由 `seed-tickets.mjs` 通过真实创建接口添加票种并触发库存预热。该脚本不覆盖已存在票种，也不重置已经发放的资格。
